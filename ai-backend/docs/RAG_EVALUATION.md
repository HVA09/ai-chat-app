# تقييم جودة استرجاع RAG

**الحالة:** مجموعة اختبار أولية وأداة قياس مضافة؛ لم تُنفَّذ حتى الآن على مزوّد embeddings حقيقي. اجتياز اختبارات الوحدة لا يعني أن جودة الاسترجاع الفعلية قد قِيست.

## الهدف والنطاق

تحتوي `tests/fixtures/rag_retrieval_eval_cases.json` على 14 سؤالًا اصطناعيًا في الشبكات وLinux وPython والسحابة والأمن وقواعد البيانات والتعليم. لكل سؤال وثيقتان ذات صلة بدرجتين (2 و1) ووثيقة مشتتة بدرجة 0، مع وصف لإخفاق مهم يجب تجنبه. توجد حالتان على الأقل في كل مجال، لكن هذا يظل حجمًا أوليًا صغيرًا لا يكفي وحده للحكم النهائي.

الأداة `scripts/evaluate_rag_retrieval.py` تختبر **ترتيب المتجهات** فقط: تحسب embeddings للوثائق والأسئلة عبر إعدادات embeddings الحالية، ثم ترتب الوثائق حسب cosine similarity، وتصدر:

- **Recall@k:** نسبة الوثائق ذات الصلة التي ظهرت ضمن أول (k).
- **Precision@k:** نسبة النتائج ذات الصلة بين أول (k).
- **nDCG@k:** جودة الترتيب مع مراعاة درجات الصلة المتدرجة؛ يمنح الوثيقة ذات الدرجة 2 وزنًا أعلى من الدرجة 1، ويكافئ ظهورها في ترتيب أعلى.
- **Reciprocal rank:** مقلوب ترتيب أول وثيقة ذات صلة؛ متوسطه عبر الحالات هو MRR.

تعد درجتا 1 و2 وثيقتين مرتبطتين عند حساب Recall وPrecision وReciprocal Rank، بينما يستخدم nDCG الفرق بين درجة الصلة 1 ودرجة الصلة 2. مجموعة البيانات الحالية تقيد الدرجات إلى 0 و1 و2، وnDCG يساوي صفرًا إذا لم توجد أي وثيقة ذات صلة.

يحتوي كل تقرير أيضًا على `dataset_sha256`، وهي بصمة ثابتة لمحتوى مجموعة التقييم، و`embedding_fingerprint` في التقرير الحي، وهي بصمة إعداد embeddings التي تتضمن المزوّد والنموذج والعنوان الأساسي والأبعاد دون عرض المفتاح أو عنوان الخدمة الخام. بذلك يمكن التأكد من أن مقارنتين تستخدمان corpus وإعداد embeddings نفسيهما قبل تفسير أي تغير في النتائج.

يعرض التقرير أيضًا `by_domain`، وهو متوسط مقاييس كل مجال على حدة. ويضيف `retrieval_diagnostics` وحقولًا لكل حالة: `top1_is_irrelevant` يحدد ما إذا كانت أول وثيقة درجتها 0، و`first_relevant_rank` يحدد موضع أول وثيقة ذات صلة، مع معدل ظهور وثيقة غير ذات صلة في المركز الأول لكل مجال. تساعد هذه الإشارات في تحديد حالات تحتاج مراجعة بشرية؛ ولا تقيّم وحدها صحة الإجابة النهائية. توجد حالتان فقط لكل مجال في المجموعة الحالية، لذا نتائج المجالات مؤشرات أولية لا أحكام نهائية على القدرة.

## التشغيل اليدوي الاختياري

من مجلد `ai-backend`، تشغيل الأداة دون خيارات أو باستخدام `--validate-only` يتحقق من مجموعة البيانات المحلية فقط:

```bash
python scripts/evaluate_rag_retrieval.py
# أو
python scripts/evaluate_rag_retrieval.py --validate-only
```

هذا هو الوضع الافتراضي الآمن. يقرأ الأمر الملف المحلي فقط، ويعرض عدد الحالات والوثائق وتوزيع المجالات ودرجات الصلة. اختبارات regression تؤكد أن هذا المسار لا يستدعي أي مزود embeddings ولا يحتاج إلى مفتاح API.

لتشغيل قياس embeddings الفعلي يجب الموافقة عليه صراحةً بإضافة `--run-live`. قد يستهلك هذا حصة مزوّد الخدمة أو يكلّف مالًا:

```bash
python scripts/evaluate_rag_retrieval.py --run-live
```

لحفظ تقرير القياس الحي إلى ملف تختاره:

```bash
python scripts/evaluate_rag_retrieval.py --run-live --top-k 3 --output reports/rag-retrieval-baseline.json
```

لا يمكن الجمع بين `--run-live` و`--validate-only`. **لا يشغّل CI القياس الحي، ولا تُرسل طلبات API إلا عند تمرير `--run-live` صراحةً.** الأداة لا تحتاج إلى اتصال بقاعدة البيانات ولا تعدّلها؛ التقرير يُطبع على الشاشة ما لم تحدد `--output`.

## تفسير الحدود

1. هذه مجموعة صغيرة اصطناعية، وليست إثباتًا لجودة المساعد على ملفات المستخدمين.
2. القياس لا يغطي جودة الإجابة النهائية، أو صحة الاستشهادات داخل المحادثة، أو التحكم في الصلاحيات، أو مقاومة prompt injection.
3. اختبار `test_retrieval_ranks_closest_embedding_first` والتحققات الأخرى في `test_rag.py` تختبر ترتيب PostgreSQL وحواجز نطاق الوصول مع متجهات مصطنعة، لا الدلالة الحقيقية لنموذج embeddings.
4. سجّل المزوّد واسم النموذج والتاريخ وإصدار مجموعة الاختبار عند مقارنة النتائج. يجب إعادة فهرسة بيانات الإنتاج بخطة منفصلة عند تغيير النموذج؛ لا يكفي تطابق الأبعاد وحده.
5. لا تسجّل مفاتيح API أو نصوص مستخدمين أو ملفات خاصة في تقارير القياس.

## بوابة قبول مقترحة

قبل ترقية نموذج embeddings، شغّل المجموعة على النموذج الحالي بوصفها baseline، ثم على النموذج المرشح، مع الحفاظ على corpus نفسه. راجع الحالات التي يكون فيها المشتت أول نتيجة حتى لو بدا متوسط المقاييس مقبولًا. لا تغيّر إعداد الإنتاج أو تعِد الفهرسة بناءً على هذا الاختبار وحده؛ يلزم تحقق منفصل من الصلاحيات وجودة الإجابات والاستشهادات، وخطة تغيير وموافقة صريحة.
