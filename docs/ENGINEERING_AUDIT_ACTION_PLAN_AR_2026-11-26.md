## 1. الهدف والنطاق

يجمع هذا الملف المهام والتوصيات المستخلصة من جولات التدقيق 226–229: جودة الاختبارات، الواجهة الأمامية، تكامل API، ودورة حياة المستخدم والجلسات والصلاحيات. هذا الملف خاص بمشروع **AI Chat App** فقط، ولا يضم خطط Lumen أو ERP أو بقية المنظومة.

الأولوية: **P1** أمان/صحة بيانات/اعتمادية عالية؛ **P2** تحسين هندسي مهم قابل للجدولة. التصنيف أولي ويجب تأكيده باختبارات إعادة إنتاج قبل التنفيذ. مراجعة الشيفرة وحدها لا تثبت وقوع استغلال أو عطل في الإنتاج.

## 2. المهام ذات الأولوية P1 — الأمان والصلاحيات

- [ ] **A1 — إبطال Access Token عند إلغاء جلسة منفردة.** ربط Access Token بمعرّف جلسة والتحقق من أن الجلسة فعالة، أو اعتماد آلية إبطال مكافئة. **القبول:** بعد إلغاء جلسة جهاز، تفشل طلباتها بينما تستمر الجلسات الأخرى المسموح بها.
- [ ] **A2 — توحيد سياسة تغيير كلمة المرور واستعادتها.** إبطال الجلسات الأخرى عند تغيير كلمة المرور وتحديد مصير الجلسة الحالية. **القبول:** اختبار يثبت إبطال الرموز والجلسات القديمة وفق السياسة.
- [ ] **A3 — إبطال الرموز عند تعطيل الحساب وإعادة تفعيله.** تحديث token_version أو إلغاء الجلسات عند انتقال حالة الحساب. **القبول:** لا يعود Access Token قديم صالحاً بعد إعادة التفعيل.
- [ ] **A4 — حماية TOTP من التخمين وإعادة الاستخدام.** إدخال محاولات 2FA الفاشلة ضمن Rate Limiting/قفل مناسب، ومنع Replay للرمز المقبول. **القبول:** لا يقبل الرمز نفسه مرتين وتُقيّد المحاولات المتكررة.
- [ ] **A5 — توحيد Workspace RBAC.** استبدال فحوص الأدوار القديمة في المسارات الحساسة بفحوص صلاحيات موحدة، مع تحويل توافق واضح للأدوار القديمة. راجع إعدادات Workspace والنموذج الافتراضي وحدود/ميزانية AI والاستخدام والتصدير. **القبول:** الدور المخصص المحدود لا يحصل على صلاحيات إضافية بسبب دور قديم مثل admin.
- [ ] **A6 — إعادة فحص صلاحيات Agent Jobs قبل الحفظ النهائي.** التحقق من حالة الحساب وعضوية Workspace والصلاحية بعد عودة مزود AI وقبل الحفظ أو نشر النتيجة. **القبول:** إلغاء العضوية أو تعطيل الحساب أثناء انتظار المزود يمنع حفظ النتيجة وكشفها.
- [ ] **A7 — حماية Lifecycle للمهام بعد الحذف أو الإلغاء.** منع العامل القديم من إكمال أثر جانبي بعد الإلغاء أو فقدان الملكية. **القبول:** اختبارات سباق وتوقف عامل وإعادة تسليم تثبت fencing ورفض النتائج المتقادمة.
- [ ] **A8 — Restore Drill معزول.** استعادة Backup في بيئة اختبار والتحقق من المخطط والبيانات وسلامة التطبيق. **القبول:** تقرير استعادة ناجحة، لا مجرد نجاح إنشاء النسخة.
- [ ] **A9 — اختبار صلاحيات Image RAG بعد انتظار Vision Provider.** تغيير ملكية الملف أو إلغاء العضوية أثناء الانتظار ثم رفض حفظ النتيجة. **القبول:** لا فهرسة أو إتاحة بعد فقدان الصلاحية.
- [ ] **A10 — اختبارات Agent Job للتزامن والتعافي.** Atomic Claim، وإعادة التسليم بعد توقف Worker، والفشل بين حفظ المهمة وإرسالها، والإلغاء أثناء انتظار المزود. **القبول:** لا تنفيذ مزدوج غير مقصود ولا حفظ من عامل قديم.

## 3. المهام ذات الأولوية P1 — Streaming وتكامل الطرفين

- [ ] **B1 — SSE Parser موحد.** استخدام محلل واحد لـ Chat وRegenerate وEdit يدعم الأحداث متعددة الأسطر وحدود الإطارات والبيانات المتبقية عند EOF وتقسيم UTF-8 بين أجزاء القراءة. **القبول:** اختبارات إطارات مجزأة وUTF-8 متعدد البايتات وإطار أخير بلا newline.
- [ ] **B2 — فرض حدث نهائي لكل بث.** التحقق من وصول done أو error؛ EOF دون حدث نهائي يُعامل كانقطاع غير مكتمل. **القبول:** لا تبقى الواجهة في حالة تحميل معلقة.
- [ ] **B3 — توحيد حالات الإنهاء.** التمييز بين Completed وUser Stopped وConnection Interrupted وProvider Failed وTimeout، وعدم اعتبار Abort نجاحاً. **القبول:** تتطابق حالة الواجهة مع حالة الرد المحفوظ ولا يعرض الجزئي كمكتمل.
- [ ] **B4 — توحيد تجديد الجلسة لطلبات Fetch Streaming.** آلية Refresh آمنة مشتركة مع Axios وإعادة محاولة للطلبات الآمنة فقط؛ منع إعادة تنفيذ آثار Agent/tools تلقائياً. **القبول:** Access منتهٍ مع Refresh صالح لا يفرض تسجيل دخول غير ضروري ولا يكرر أدوات Agent.
- [ ] **B5 — اختبارات النقل والأعطال.** انقطاع المزود بعد أول Chunk، وخمول البث، وفشل حفظ الرد، وانقطاع Redis، وطلبات متزامنة للمحادثة. **القبول:** حالة نهائية واضحة بلا بيانات مضللة.

## 4. جودة الاختبارات والبيانات والأداء

- [ ] **C1 (P2) — اختبارات Streaming Concurrency.** EOF دون done، وتجديد Cookie أثناء البث، وانقطاع Redis، وتزامن المحادثة. **القبول:** لا اختلاط رسائل ولا فقدان حالة نهائية.
- [ ] **C2 (P2) — Performance Suite مستقلة.** قياس RPS وP95/P99 وDatabase Pool Saturation وRedis Throughput وStreaming Concurrency وMemory Growth وQueue Backlog في بيئة اختبار فقط. **القبول:** Baseline وحدود إنذار قابلة للمقارنة.
- [ ] **C3 (P2) — تقوية Migration Tests.** اختبار الترقية من مخططات سابقة متعددة مع Restore Drill قبل التغييرات الحساسة. **القبول:** لا فقد بيانات ولا اختلاف غير متوقع بين ORM والمخطط.

## 5. الواجهة وتجربة الاستخدام (P2)

- [ ] **D1 — استبدال مفاتيح الرسائل المعتمدة على index بمعرّفات ثابتة.** **القبول:** حذف/إدراج/إعادة ترتيب الرسائل لا ينقل الحالة المحلية بين الرسائل.
- [ ] **D2 — تحسين الوصول إلى Message Actions.** إظهار الإجراءات الأكثر استخداماً بصورة موجزة ووضع الأقل استخداماً في قائمة إضافية. **القبول:** اكتشاف النسخ والقراءة الصوتية وإعادة التوليد والتعديل والحذف بسهولة على الهاتف وسطح المكتب.
- [ ] **D3 — تبسيط Sidebar دون حذف الوظائف.** جعل المحادثات محور التنقل، وتنظيم المشاريع والمجلدات والمساعدين والأدوات في أقسام قابلة للطي. **القبول:** لا تداخل أو ازدحام على الهاتف مع بقاء الوظائف متاحة.
- [ ] **D4 — ضبط Composer.** تقليل حجم زر الإرسال وتحسين توزيع الأدوات والمرفقات دون تغيير السلوك. **القبول:** استخدام مريح على الهاتف وسطح المكتب.
- [ ] **D5 — تحسين المحادثات الطويلة.** قياس الأداء ودراسة Virtualization عند الحاجة واختبار Auto Scroll. **القبول:** لا تدهور ملحوظ في التمرير أو الذاكرة.
- [ ] **D6 — تنظيم App.jsx وCSS تدريجياً.** فصل المسؤوليات دون إعادة كتابة شاملة. **القبول:** اختبارات الواجهة والبناء تمر بعد كل تغيير.
- [ ] **D7 — مراجعة تحميل الصور الخارجية في Markdown.** توثيق سياسة الخصوصية وتقييد/تعطيل التحميل التلقائي عند الحاجة لتجنب تسريب IP أو بيانات الطلب. **القبول:** سياسة واضحة واختبار للسلوك.

## 6. عقود API والإشعارات والملفات (P2)

- [ ] **E1 — توحيد تنزيل الملفات** عبر filesApi بدلاً من روابط مباشرة متفرقة. **القبول:** تنزيل خاص للمصرح به ورفض غير المصرح به.
- [ ] **E2 — تقييد Notifications Pagination.** حد موجب وأعلى واضح (مقترح 1–100). **القبول:** رفض القيم خارج النطاق برسالة تحقق سليمة.
- [ ] **E3 — إعادة التحقق من صلاحية WebSocket.** التعامل مع إلغاء الجلسة أو تغيير token_version أثناء اتصال طويل العمر. **القبول:** الاتصال الملغى لا يتلقى إشعارات بعد مهلة/إشارة الإبطال المحددة.
- [ ] **E4 — Contract Tests بين الطرفين.** تغطية الحقول والأنواع والأخطاء وPagination وملفات وChat وNotifications وSSE. **القبول:** التغيير غير المتوافق يفشل قبل الدمج.

## 7. سلسلة التوريد وقابلية إعادة البناء (P2)
