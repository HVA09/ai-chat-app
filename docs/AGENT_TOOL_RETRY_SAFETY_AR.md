# سلامة إعادة محاولة Agent واستدعاء الأدوات

## الهدف

منع تكرار عمليات قد يكون Agent نفّذها بالفعل، ومنع عرض نص كتبه النموذج على أنه استدعاء أداة تم تنفيذه.

## عقد إعادة المحاولة

- قبل بدء أي أداة: إذا فشل تشغيل Agent ولم يبدأ أي حدث `start`، يُرسل الخادم `retry_mode=send`. يمكن للواجهة إعادة إرسال الطلب الأصلي مع سياقه وملفاته.
- بعد بدء أداة واحدة على الأقل: إذا فشل Agent قبل إكمال الدور، يُرسل الخادم `retry_mode=blocked`. لا تنشئ الواجهة بيانات إعادة محاولة ولا تعرض زر إعادة المحاولة التلقائية.
- يُعامل حدث بدء الأداة كحد محافظ؛ فالنتيجة قد تكون غامضة عند timeout أو انقطاع الاتصال، وقد تكون الأداة أحدثت أثرًا محليًا أو في قاعدة البيانات أو في نظام خارجي.
- لا يعني الحظر أن الأداة فشلت أو نجحت؛ بل يعني أن إعادة المهمة كاملة ليست آمنة دون مراجعة الحالة أولًا.
- هذا التغيير لا يضيف نظام استئناف أو idempotency key. يمكن دراسة ذلك لاحقًا في نطاق مستقل.

## عقد استدعاء الأدوات

يجب أن تصل استدعاءات الأدوات عبر الحقل المنظم `tool_calls`، ثم تُمرر إلى Registry المعتمد. لا تُنفذ أو تُعرض صيغ pseudo-call النصية على أنها عمليات فعلية.

تتعرف طبقة Agent على صيغ واضحة تبدأ بـ `//` مثل `// tool_call` أو `// call_tool` أو `// invoke_tool`، أو JSON يشير إلى اسم أداة مسجلة، أو استدعاء مباشر بصيغة `// tool_name(...)`. عند اكتشافها دون `tool_calls` منظم:
- لا يُستدعى أي Handler.
- لا يُعاد النص الخام كإجابة ناجحة.
- ترجع الحالة `stopped` مع توضيح أن الأداة لم تُنفذ.

تُترك التعليقات البرمجية العادية مثل `// calculator is an example` كنص عادي؛ ولا يُعد وجود `//` وحده خطأ بروتوكول.

## أحداث البث

يجب أن تُرسل أحداث Agent بصيغة SSE حقيقية باستخدام فواصل الأسطر، حتى يتمكن العميل من فصل أحداث `tool` و`retry_mode` و`chunk` و`done` ومعالجتها.

## الاختبارات

تغطي اختبارات الانحدار:
- Agent يفشل قبل بدء أي أداة: يسمح بإعادة إرسال الطلب الأصلي.
- Agent يفشل بعد حدث بدء أداة: يرسل `blocked` ولا يعرض إعادة المحاولة.
- صيغ pseudo-call المعروفة لا تُنفذ ولا تظهر كنجاح.
- تعليق JavaScript عادي لا يُصنف كاستدعاء أداة.
- واجهة SSE تنقل `retryMode` بدقة، وتزيل إمكانية إعادة المحاولة عند الحظر.

## النطاق والسلامة

التغيير خاص بمنطق Agent، وSSE، واختبارات الانحدار، وهذه الوثيقة. لا يغير قواعد الأدوات المسموحة، ولا إعدادات MCP، ولا بيانات الإنتاج، ولا الأسرار، ولا إعدادات Render أو Supabase. يجب إبقاء PR بحالة Draft حتى اكتمال CI وCodeQL ومراجعة المالك.
