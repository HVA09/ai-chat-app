**آخر تحديث:** 16 نوفمبر 2026
**المستودع:** `HVA09/ai-chat-app`  
**الفرع الأساسي:** `main`  
**آخر رأس تم التحقق منه عند إعداد السجل:** `7a3289ca43070bc8fdff925dbe98fcbbbbade3df`

**حدود هذا السجل:** يخص AI Chat App وحده، ولا ينقل خطط Lumen أو ERP إلى هذا المستودع.

> هذه الوثيقة طبقة حوكمة مختصرة وليست بديلاً عن خارطة الطريق التفصيلية أو سجل الاستمرارية أو وصف طلبات الدمج. قبل أي تنفيذ جديد، يجب إعادة قراءة الحالة الحية لـ main وطلبات الدمج وفحوص CI.

## 1. دور المنتج داخل المنظومة الأوسع

AI Chat App هو تطبيق محادثة ومساعد ذكي مستقل. يمكنه مستقبلاً استهلاك خدمات AI Core من خلال API موثقة ومؤمّنة، لكنه لا يحتوي كود Lumen أو ERP، ولا يعتمد على قواعد بياناتهما أو نشرهما لتقديم وظائفه الأساسية.

- يبقى مستودع التطبيق وقاعدة بياناته وأسراره ونشره واختباراته مستقلة.
- لا تُنقل وظائف النواة المركزية إلى هذا المستودع لمجرد أن التطبيق سيكون أحد مستهلكيها.
- تعطل خدمة AI Core يجب ألا يؤدي إلى انهيار التطبيق بالكامل؛ تُستخدم مهلات اتصال، وفشل مضبوط، ورسائل واضحة ومسار تشغيل محدود حيث يكون ذلك ممكناً.

## 4. الأولوية التنفيذية الحالية

**الأولوية الأولى: استكمال الاستقرار والقبول التشغيلي قبل التوسع الوظيفي.**

1. مواصلة فحص مسارات تسجيل الدخول والجلسات وقاعدة البيانات والبث والمهلات، مع التمييز بين إصلاحات main والمشكلات التي ما زالت تحتاج إعادة إنتاج.
2. تنفيذ قبول يدوي على Android للهاتف والملفات والقائمة الجانبية وإجراءات الرسائل والصوت، وعدم اعتبار واجهة الويب دليلاً كافياً على نجاح تجربة الهاتف.
3. متابعة سجلات النشر وفحوص health/readiness ونسخ قاعدة البيانات والاستعادة، دون إنشاء موارد مدفوعة أو تعديل الإنتاج بالتخمين.
4. التعامل مع PR #665 عبر التقسيم التدريجي فقط؛ لا إعادة فهرسة أو embeddings واسعة أو تغييرات مكلفة قبل توثيق الخطة والتكلفة والاختبارات.
5. إبقاء AI Core والتكاملات المشتركة الكبيرة مؤجلة حتى ثبات التطبيق وعقود البيانات والصلاحيات.

## 5. سياسة التطوير والدمج

- لا إعادة كتابة شاملة للغات أو الأطر لمجرد تغيير التقنية.
- لا دمج لـ PR كبير أو متعارض اعتماداً على وصفه أو نجاح اختباراته القديمة.
- يمكن تسريع تغييرات التوثيق والإصلاحات الصغيرة منخفضة المخاطر بعد مراجعة نطاقها وفحوصها.
- لا تجاوز لحماية main أو متطلبات CI.
- لا اختبارات مزود AI حيّة أو إعادة فهرسة كبيرة أو تغييرات بنية تحتية قد تستهلك رصيداً أو تفرض تكلفة دون قرار واضح.
- كل مرحلة توثق: الهدف، الفرع وPR والـcommit، الملفات المتغيرة، نتائج CI/CodeQL والاختبار التشغيلي، والمخاطر والقرار التالي.

## 6. حدود التكامل مع AI Core

عند بناء AI Core كمستودع مستقل:

- يكون الاتصال عبر عقود API versioned ومصادقة خدمة إلى خدمة.
- تبقى هوية مستخدمي التطبيق وصلاحياتهم وبيانات محادثاتهم في نطاق التطبيق، ولا تنتقل تلقائياً إلى نواة مشتركة.
- مشاركة الملفات أو المحادثات أو الذاكرة تتطلب نطاق صلاحية وموافقة وسياسة احتفاظ واضحة.
- تُدار حدود الاستخدام والمهل وإعادة المحاولة ودوائر فصل الأعطال (circuit breakers) بصورة مستقلة.
- لا يصبح AI Core نقطة فشل وحيدة؛ يجب توفير سلوك fallback آمن عند الانقطاع.

## 7. ما لا يدخل في هذا المستودع

- منصة Lumen التعليمية ومخطط بياناتها وخدماتها.
- ERP Global Pro وبيانات الشركات والمعاملات المالية.
- منصة المعمارية العامة أو مستودع AI Core المستقبلي.
- لا تُضاف وثائق المنظومة الكاملة هنا إلا إحالات قصيرة إلى المستند المعماري العام.

## 8. قاعدة تحديث هذا السجل

بعد كل تغيير مؤثر، يُحدّث السجل من الأدلة الفعلية في GitHub وCI والخدمة. لا تُنسخ حالات قديمة من المحادثات إلى السجل الحالي دون إعادة تحقق. إذا تعارض هذا الملخص مع أحدث كود أو workflow أو سجل استمرارية تفصيلي، يُراجع الدليل الأحدث ويُصحح الملخص في PR مستقل.

**القرار المعماري:** AI Chat App منتج مستقل ضمن منظومة أوسع؛ خطته الخاصة تحكم تطويره اليومي، والخطة الرئيسية للمنظومة تحكم واجهات التكامل المستقبلية فقط.
